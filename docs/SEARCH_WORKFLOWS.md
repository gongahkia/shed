# Search workflows

Use Edit → Find in Files, Ctrl/Cmd+Shift+F, the command palette, or `:findinfiles` to open Search. The panel retains controls and results when switching documents. Search runs on a worker, streams batches, and stops when Cancel or Escape is pressed. Editing a query cancels the previous request, clears stale results, and starts a new search after a short pause. Down focuses results; Enter or a double click opens the exact line and column. Escape returns to the editor. Results remain separate from source documents and also populate quickfix navigation.

Inline Find, Search and replacement previews use the same case-sensitive (default), Unicode whole-word, and Java regex matching rules. Whole-word boundaries include letters, combining marks, numbers and underscore. Whitespace in UI queries is significant. Invalid or excessively complex regexes show an error; matching checks cancellation during backtracking and has a one-second budget per matcher. Inline highlights are bounded around the current result, while counts retain at most 200,000 ranges.

Workspace Search streams UTF-8 files line by line, so regexes that consume newlines are only supported by current-file search/replacement and the full-document replacement preview. Search skips symbolic links, binary lines and unreadable files; ignore rules and imported search exclusions remain in effect. The workspace result limit is 200 and reports whether additional matches actually exist. An exact 200-match result is complete. Overlapping workspace roots do not duplicate physical files.

Include and Exclude accept comma-separated root-relative globs. `**/*.{java,kt}` includes Java and Kotlin at any depth, including the workspace root. `build/**,**/generated/**` excludes generated directories. A pattern without `/` also matches basenames. Exclusions win, and includes cannot override workspace ignore rules.

**In Files** transfers the inline query and options to Search; **Current File** transfers them back. **Replace…** also carries the include/exclude filters to Replace. Enable project replacement explicitly, enter replacement text, then Preview. Literal mode preserves `$` and backslashes; regex mode supports `$1` and `${name}` groups. Review each expanded replacement and deselect individual files/matches before Apply Selected. Changing any query, replacement, filter or scope invalidates the previous preview. Discard also invalidates an in-flight preview.

Apply requires a complete preview and confirmation. Selected files with unsaved editor changes block application; files changed on disk since preview are skipped. Existing atomic writes and configured backups remain in use. A workspace replacement updates disk files; existing external-change handling reconciles open documents. It is not one global editor undo transaction. Current-file Replace All remains a single undo operation.
